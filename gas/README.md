# 金煎坊線上訂單 → Google Sheet 串接說明

網站結帳時，訂單會送到 Google Apps Script（GAS），再寫入你的 Google 試算表。

```
顧客按「確認送出訂單」 → index.html 送出 JSON → GAS 網頁應用程式 (Code.gs)
                                                ├─ 驗證資料、產生訂單編號
                                                ├─ 寫入「訂單」「訂單明細」工作表
                                                └─ （可選）寄 Email 通知店家
```

## 一、建立試算表與 GAS（約 5 分鐘）

1. 開一個新的 Google 試算表，例如命名為「金煎坊訂單」。
2. 上方選單點 **擴充功能 → Apps Script**。
3. 把編輯器裡的預設內容全部刪掉，貼上本資料夾的 `Code.gs`，按儲存。
4. （可選）想收到新訂單通知信，就把 `NOTIFY_EMAIL: ''` 改成你的 Email。
5. 上方函式選單選 **setup**，按 **執行**。
   - 第一次會跳出授權視窗：選你的帳號 →「進階」→「前往（不安全）」→「允許」。
   - 完成後試算表會多出「訂單」與「訂單明細」兩個工作表。

## 二、部署成網頁應用程式

1. 右上角 **部署 → 新增部署作業**。
2. 類型選 **網頁應用程式**。
3. 設定：
   - 執行身分：**我**
   - 誰可以存取：**所有人**（顧客不需登入 Google 才能下單）
4. 按 **部署**，複製「網頁應用程式網址」（`https://script.google.com/macros/s/…/exec`）。
5. 用瀏覽器打開這個網址，看到 `{"ok":true,"service":"golden-pan-orders"}` 就代表成功了。

## 三、把網址填進網站

打開 `index.html`，找到這一行：

```js
const GAS_URL = '';
```

把網址貼進引號中，存檔並推上 GitHub：

```js
const GAS_URL = 'https://script.google.com/macros/s/你的部署ID/exec';
```

`GAS_URL` 空著的時候，網站是**示範模式**：結帳會照常顯示成功畫面，但不會真的送出訂單。

## 試算表欄位

**訂單**（一張訂單一列）

| 訂單編號 | 建立時間 | 狀態 | 取餐方式 | 姓名 | 手機 | 門市 | 預計時間 | 宅配地址 | 備註 | 品項摘要 | 小計 | 運費 | 應付金額 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

- 「狀態」是下拉選單：新訂單 → 製作中 → 可取餐／已出貨 → 已完成／已取消，店員可以直接在試算表上更新。
- 訂單編號格式為 `GP20261127-0001`，每天從 0001 重新編號。

**訂單明細**（每個品項一列，方便做銷售統計或樞紐分析）

| 訂單編號 | 建立時間 | 品項ID | 品名 | 單價 | 數量 | 小計 |
|---|---|---|---|---|---|---|

## 已處理的細節

- **同時下單不會撞號**：用 `LockService` 鎖定後才產生編號。
- **資料驗證**：手機格式、必填欄位、數量上限（每項 99 份、每單 50 項）都會在 GAS 端再檢查一次。
- **防機器人**：表單裡有一個真人看不到的欄位，有被填寫的訂單會直接丟棄。
- **防公式注入**：顧客輸入的文字一律以純文字寫入，不會被試算表當成公式執行。
- **送出失敗**：網站會顯示錯誤訊息，購物車與已填資料都會保留，可以直接再按一次。

## 修改 Code.gs 之後

每次修改都要重新部署才會生效：**部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**。
這樣網址不會改變，不用再改 `index.html`。

## 注意

- 品項價格目前由網站送出。若有人刻意竄改價格，GAS 只會擋掉負數或格式錯誤的數值，不會比對菜單價格。之後如果要接線上付款，建議在試算表另外建一張「商品價格」表，由 GAS 依品項 ID 重新計算金額。
- Google 免費帳號的 Apps Script 有每日執行次數與寄信數量上限（寄信約每天 100 封），一般小店的訂單量通常用不完。
